## Why attempts 1–2 failed (environment, not code)

- **Line endings.** Under `* text=auto`, Git on Windows checks out text files with CRLF unless a pattern gives
  `eol=lf`.
  - Two `CanonicalJsonTests` fail at `CanonicalJsonTests.cs:138`: the golden hex file contains `\r`.
  - Two Benchmarking tests fail with "Tiny protocol fixture must use complete LF-framed NDJSON"
    (`TinyProtocolFixtureCompiler.cs:359`): `TinyProtocolFixtureCompilerTests` and `TinyPairedHarnessProcessTests`.
  - These four pass once the clone uses `core.eol=lf`. The fifth failure is the clean-tree case below.
- **Clean tree.** `StrictBagItBundleTests.Source_inventory_binds_dirty_worktree_files_not_only_base_commit` asserts
  `inventory.GitDirty` (`StrictBagItBundleTests.cs:32`).
  - `GitDirty` is true when `git status --porcelain=v1 --untracked-files=all` is non-empty
    (`BundleSourceInventoryCapture`, lines 48-50 and 113).
  - A fresh clone is clean, so the test cannot pass there. With one untracked file it passes (attempt 3b).
  - The test therefore assumes a working tree with uncommitted files. This is a test-design dependency, not a
    production defect.
