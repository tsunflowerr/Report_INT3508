The service area divides into 69 Manhattan taxi zones, time periods into 5-minute intervals (288 total), yielding 19,872 total states. ## Reward Structure
"The reward for an agent at time index t is defined as the number of new requests that have been assigned to the agent in that time index." Rewards can be zero or positive integers, reflecting requests matched to a vehicle within each period.

## N-Step TD Learning
Uses n=12 steps (one-hour lookahead with 5-minute intervals). The update formula incorporates observed rewards across 12 future steps plus discounted value of the resulting state: "Gt:t+nv=rt+1v+γrt+2v+…+γn−1rt+nv+γnV(St+n)". Discount factor γ=0.9.

# NeurADP: Ride-Pooling Analysis

## (1) MDP State Definition

The state is defined as **s_t = (r_t, u_t)** where:
- **r_t**: vehicle states, each represented as r_t^i = (p^i, t, L^i)
  - p^i: current location
  - t: current time
  - L^i: ordered list of future locations to visit
- **u_t**: all waiting user requests, each as u_t^j = (o^j, e^j)
  - o^j: origin location
  - e^j: destination location

## (2) Value Function Decomposition

The approach uses **per-vehicle decomposition with summed individual value functions**:

"V(r_t^a) = ∑_i V^i(r_t^a)" where each V^i approximates individual vehicle rewards. The decomposition assumes individual vehicle long-term rewards are not significantly affected by other vehicles' current actions, allowing use of "pre-decision, rather than post-decision, state of other vehicles."

## (3) Value Injection into ILP Objective

The learned value is added as a constant term in the assignment ILP (Table 1):

**max ∑_i ∑_f∈F_t^i [o_t^{i,f} × a_t^{i,f} + V^i(T^{i,a}(r_t^{i,a},f)) × a_t^{i,f}]**

The neural network value function is "evaluated for all possible r_t^{i,a}" offline, then integrated as constants.

## (4) Training Data Volume

- **Training days**: 8 weekdays (23 March – 1 April 2016)
- **Request volume**: Average 322,714 requests/weekday in dataset; 19,820 during peak hour
- **Training time**: Not explicitly stated; paper notes feasible action generation was "bottleneck" requiring multiple training days

## (5) Experimental Setup

- **Fleet size**: 1000–3000 vehicles tested
- **Request volume per interval**: Decision epoch Δ = 60 seconds
- **City**: Manhattan, New York (4,373 street intersections, 9,540 edges)
- **Max waiting time**: τ ∈ [120, 420] seconds
- **Max detour delay**: λ = 2τ

## (6) Reported Improvement

"NeurADP obtains a 16.07% improvement over the baseline approach for τ=120 seconds." Improvements range from ~6% to ~47% depending on parameters; paper claims "40% relative improvement" versus baseline.

## (7) Request Re-assignment and State Commitments

**No re-assignment**: "all user requests that are not assigned are lost." Once assigned, requests cannot be reassigned to different vehicles.

**No explicit promise tracking**: The state does not track promised pickup times as separate commitment variables. The trajectory L^i implicitly encodes pickup/dropoff sequence and deadlines, but the model does not maintain an explicit "promised time" distinct from the current trajectory state.

# Zone Path Construction (ZAC) for Real-Time Ridesharing: Key Findings

## (1) Zone Path Definition and Generation

A **zone** is "an abstracted location obtained by clustering locations" in the road network. A **zone path** is "an ordered sequence of nodes, where each node corresponds to either a location...or a zone."

The offline-online generation strategy works as follows:
- **Offline**: Generate all partial location paths spanning maximum wait time τ from every location
- **Online**: Load these partial paths, process them based on current requests, and complete them using exhaustive search with zone-level granularity to reduce computational complexity

## (2) Non-Myopic Value Function in ZACBenders

Rather than learning a value function, ZACBenders employs a **two-stage stochastic approximation**:
- **Stage 1**: Assigns current requests to zone paths (tripartite matching)
- **Stage 2**: For each demand sample, solves weighted bipartite matching between vehicles and future requests at zone level

The approach uses **Benders decomposition**, solving LP duals of slave problems to generate optimality cuts added to the master problem iteratively. No neural network learning involved—it's purely optimization-based.

## (3) Request Re-assignment Policy

"Once a vehicle is assigned to a set of requests at any decision epoch, the assignment is not changed but the path of vehicle can change at next decision epoch to accommodate additional requests."

This means already-picked-up requests cannot be re-assigned, but vehicles can accept new requests at subsequent epochs.

## (4) Experimental Setup

**Datasets**: New York Yellow Taxi (Manhattan, 4,373 locations), confidential Dataset1 (21,212 locations), and synthetic first/last-mile scenario (192 locations)

**Fleet parameters tested**:
- Vehicle capacity κ: 2–6 passengers
- Decision epoch Δ: 30–120 seconds
- Maximum wait τ: 120–420 seconds
- Maximum delay λ: 600–1,200 seconds
- Fleet sizes varied to test scalability

## (5) Reported Improvements

**vs. Trip-Based Formulation (TBF)**:
- ZAC: up to 4% improvement on real-world; 20% on synthetic
- ZACBenders: 14.7% improvement

**vs. NeurADP**:
- When NeurADP is not hyperparameter-optimized to test settings: ZACBenders achieves "up to 12.48% improvement"
- When NeurADP is hyperparameter-optimized: "results largely remain comparable except in a couple of cases, where NeurADP performs better"

## (6) Promises/Guarantees

The paper makes no explicit guarantees regarding customer satisfaction or commitment promises. It addresses operational objectives (maximizing requests served, minimizing delay) within stated constraints (τ maximum wait, λ maximum delay), but these are system parameters—not commitments to customers.
