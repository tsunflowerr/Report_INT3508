# Ride-pool Assignment Algorithms: Key Findings

## Swapping Heuristics Definitions

**LA-MR (Multi-Round Linear Assignment):** Performs multiple rounds of bipartite matching within a single epoch. After the initial assignment, unserved requests can be reconsidered across rounds, allowing vehicles to receive multiple assignments sequentially rather than all at once.

**LA-MR-NS (Naive Swapping):** Extends LA-MR by adding duplicate nodes for already-assigned requests. "A naive swap δ(r,f₁→f₂) reassigns request r from trip f₁ to trip f₂" with cost reduction calculated independently for each swap.

**LA-MR-CE (Cyclic Exchange):** Uses "Maximum weight cycle" detection rather than single swaps. The approach constructs graph G_CE with requests and vehicles as nodes, identifying "valid cycles" where no two requests belong to the same vehicle and at most one vehicle node appears per cycle.

# Analysis of LRP Heuristic and Experimental Results

## (a) LRP "Limit and Recall Prefix" Heuristic

**Full Definition:**
The LRP heuristic is a threshold-enabled approach activated when total nodes exceed parameter η ∈ ℕ₊. It operates by:

1. Recalling the previous vehicle route from memory
2. Removing nodes already visited by iteration start
3. Identifying a prefix S̄ ⊆ S such that |S̄| + |ℛ| = η (where S̄ is kept fixed, S̲ = S \ S̄ is the suffix)
4. Using exact recursive search to optimally insert all nodes from S̲ + ℛ into prefix S̄ while "keeping the order of S̄ intact"

**Threshold Parameter:**
η determines the cutoff for triggering the heuristic. Each onboard passenger contributes 1 node (drop-off only); each pending request contributes 2 nodes (pick-up + drop-off). If |ℛ| > η, the heuristic returns no solution.

**Complexity:**
Polynomial time for the heuristic framework, but employs exact recursive search on the constrained subproblem (exponential in worst case, but limited to η nodes).

**Stability:**
"LRP heuristic is also stable" per Definition 6.1, guaranteeing consistent ordering of common nodes across re-computations.

## (b) Prefix/Suffix and Frozen-Node Handling

LRP explicitly manages:
- **Prefix S̄**: Fixed and preserved during optimization
- **Suffix S̲**: Reoptimized with new requests ℛ
- **On-board Order Fixing (OOF)**: Predecessor heuristic that "fixes the order of drop-off nodes of all onboard passengers"

This differs from naive insertion, which doesn't preserve earlier decisions.
